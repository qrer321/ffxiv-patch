### 게임 업데이트 뒤 강제 종료를 일으키는 패치 생성 차단

- 7.58 업데이트 뒤 패치를 적용한 클라이언트가 강제 종료된다는 제보가 있었습니다. 업데이트 이전 버전의 index를 기준으로 패치가 만들어진 것이 원인이었습니다. 이렇게 만든 패치는 업데이트로 바뀐 시트를 다른 시트의 데이터로 채웁니다.
- 이전 실행 파일은 게임 업데이트 뒤 **패치 제거**를 누르면, 업데이트로 새로 받은 index를 저장해 둔 이전 버전 index로 덮어쓸 수 있었습니다. 이제 패치가 남아 있는 index만 되돌리고, 새로 받은 index는 그대로 둡니다.
- 패치를 만들기 전에 기준 index가 현재 게임 데이터와 맞는지 확인하고, 맞지 않으면 만들지 않습니다.
- 사전 점검이 이전 버전 index가 설치된 상태를 찾으면 패치 버튼을 잠그고 런처 파일 검사/복구를 안내합니다. 패치 제거 결과 창에도 같은 안내가 나옵니다.

**사용 방법**
- 게임 업데이트 뒤 사전 점검이 이미 한글 패치가 적용된 상태라고 안내하면, 새 실행 파일에서 **패치 제거**를 누른 뒤 다시 패치해 주세요. 런처 복구는 필요 없습니다.
- 이전 실행 파일로 7.58 업데이트 뒤에 패치 제거나 패치를 이미 진행했다면, 사전 점검이 `0a0000.win32.index` 항목이 dat 파일과 맞지 않는다고 알릴 수 있습니다. 이때는 런처의 파일 검사/복구로 글로벌 서버 클라이언트를 원본으로 되돌린 뒤 다시 패치해 주세요.

**확인 상태**
- 릴리즈 빌드가 경고 0개·오류 0개로 완료됐고, 배포 EXE에 내장된 제너레이터·폰트 패키지·RSV 맵의 해시가 빌드 입력과 같음을 확인했습니다.
- 7.58 글로벌·한국 클라이언트 파일의 사본으로 확인했습니다. 7.58 이전 index를 기준으로 하면 수정 전 제너레이터는 크래시 로그와 일치하는 15행짜리 시트를 만들고, 수정 후 제너레이터는 생성을 중단합니다. 정상 index 기준 출력은 수정 전후가 바이트 단위로 같습니다.
- 패치 제거와 복구 기준 처리는 실제 index 파일로 만든 가상 설치 폴더에서 수정 전후 동작을 비교했고, 릴리즈 빌드의 사전 점검·패치 제거 화면도 같은 가상 폴더에서 확인했습니다. index 검사 회귀 테스트 27개를 통과했습니다.
- 실제 게임에서의 크래시 재현과 수정 후 확인은 하지 않았습니다.

크래시 로그를 제보해 주신 분께 감사드립니다.
