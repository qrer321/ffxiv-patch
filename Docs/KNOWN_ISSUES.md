# 현재 알려진 제한 사항

이 문서는 현재 동작에 영향을 주는 제한과 회귀 방지 규칙만 기록한다. 과거 실험 산출물, 폐기된 구현의 상세 이력, 세션별 작업 로그는 포함하지 않는다.

## 게임 업데이트 뒤 이전 버전 index로 인한 강제 종료

7.58(`2026.11.03.0000.0000`) 적용 사용자의 Dalamud 크래시 로그(`LuaEventHandler.vf49+0x64`, null 읽기)를 분석한 결과다.

- 원인: 7.58 이전에 저장된 `0a0000.win32.index`를 기준으로 7.58 `dat0`에서 패치를 생성·적용한 상태. 게임 업데이트는 바뀐 파일의 예전 dat 블록을 비우거나 다른 파일에 재사용하므로, 이전 index는 바뀐 시트를 빈 블록이나 다른 시트의 파일로 보낸다.
- 로그의 사례: `custom/003/CtsEtcBoosterLogin_00392`는 7.58에서 28행 → 40행으로 바뀌었다. 이전 index로 읽으면 일본어 EXD 자리에 `FesNyx2027Guide_00939`의 15행 EXD가 있고, EXH는 같은 위치에 덮어써져 40행이다. 생성기는 `custom/` 시트를 행 번호로 대응시켜 키·본문을 한국어 행으로 덮어쓰므로 0~14행만 있는 EXD가 만들어진다. 클라이언트는 EXH의 캐시 크기(24)만큼 0~23행을 한 번에 요청하고, 찾지 못한 15행의 null 포인터를 그대로 읽는다.
- 재현: clean 7.58 글로벌·한국 데이터의 사본(사용자 승인을 받아 설치 폴더에서 필요한 파일만 복사)으로 확인했다. 정상 index 기준 출력은 40행이고, 7.58 이전 index 기준 출력은 15행이며 14행의 키·본문 첫 바이트, 행 묶음 크기 24, 실패 인덱스 15가 로그와 일치한다.
- 조치
  - 제너레이터는 텍스트 패치 기준 index/index2의 모든 항목이 글로벌 dat 파일의 실제 파일 레코드를 가리키는지 확인하고, 아니면 생성을 중단한다(`SqPackIndexCheck`). 재현에 쓴 이전 index는 37,872개 중 15개가 걸린다. 정상 7.58 index는 글로벌 37,872개·한국 16,095개 모두 통과한다.
  - UI의 `한글 패치 제거`·`백업으로 복구`는 패치 엔트리가 없는 index를 덮어쓰지 않는다. 패치된 index는 "설치된 index에서 패치 리다이렉트만 뺀 것"과 항목이 같은 index로만 되돌린다. 복구 기준(`restore-baseline`)도 같은 조건으로 저장하며, 맞지 않는 기존 기준은 버리고 다시 만든다.
  - 사전 점검은 설치된 `0a0000` index/index2에 같은 검사를 적용하고, 실패하면 패치 버튼을 잠그고 런처 파일 검사/복구를 안내한다. 패치 제거 뒤에 남은 index가 이 검사에 걸리면 제거 결과 창의 `다음 패치`에도 런처 파일 검사/복구가 필요하다고 표시한다.
- 한계
  - dat 레코드 검사는 `0a0000`(텍스트)에만 적용한다. `000000`·`060000`은 UI의 복구 조건으로만 보호한다.
  - 검사는 업데이트가 해제한 레코드(type 0)와 레코드가 아닌 위치만 잡는다. 빈 placeholder 파일(type 1)은 정상 항목이다. 글로벌 7.58의 `000000` index는 265개 중 42개가 `common/font`의 빈 placeholder를 가리키고, 검사 결과는 0건이다. `060000`은 실제 데이터로 확인하지 못했다.
  - 이미 이전 index가 설치된 클라이언트는 도구가 고칠 수 없다. 런처 파일 검사/복구가 필요하다.
  - 업데이트가 바꾼 모든 파일의 예전 위치가 다른 파일의 시작 위치로 정확히 재사용되면 dat 레코드 검사로는 잡히지 않는다.
- 미확인
  - 실제 게임에서의 크래시 재현과 수정 후 확인은 하지 않았다.
  - 제보자가 어떤 경로로 이전 index를 기준으로 쓰게 됐는지는 확인하지 못했다. 수정 전 UI는 `업데이트 → 제거`에서 이전 버전 index를 덮어쓸 수 있었고(실제 index로 시뮬레이션 확인), 첫 사전 점검 때 `0a0000` index에 패치 엔트리가 남아 있으면 그 index가 새 버전의 복구 기준으로 저장됐다. 런처 업데이트가 `0a0000` index를 통째로 교체하는지는 확인하지 못했다.

## 사용자 보고로 확인된 마수조련사 문제

사용자 제보와 v7.56 데이터 점검으로 파악한 항목이다. 번역·발바닥 복원은 유지하고, 제목·랭크업은 원본 ULD와 직접 한글을 유지한 크기 조정본으로 테스트한다. 아래 데이터 검증과 실제 게임 화면 확인을 구분한다.

### 마수도감 제목·랭크업 — 기준선 유지 및 실제 크기 추가 축소

- 글로벌·한국어 원본 ULD는 동일하며, 원본 `TrumpGothic_23.fdt`도 동일한 211글리프 파일로 한글이 없다. TTMP에는 한글이 직접 추가돼 있다.
- 직전 기준선 수정본 대비 Trump23 제목 전진 폭은80→72, 가시 크기는77×20→69×18이다. 랭크업 전진 폭은112→102, 가시 크기는111×20→101×19이다. 실제 생성 FDT/텍스처 측정이며 클라이언트 배율 적용 전 값이다. 영문·기호는 줄이지 않아 느낌표를 포함한 전체 높이는 한글 축소율과 같지 않다.
- 원본 글자도 ULD 템플릿 폭·높이보다 크므로 이를 그대로 클리핑 한계로 해석하지 않는다. 앞서 추가했던 제목 AXIS18, 랭크업 AXIS12/높이20 보정은 제거했다. 두 ULD와 원문 부제는 원래 설정을 유지한다.
- 직접 한글을 제거한 비교본은 사용자 게임에서 제목이 `====`로 표시되어 폐기했다. 한글/자모 등록, 기존 크기 보정과 패치 출력 기반 글자 수집을 복구했다.
- 비로비 `TrumpGothic_23/34/68.fdt`의 한글 크기 목표를0.98→0.88로 약10.2% 더 낮췄다. 기존 가시 하단 기준선 보정은 유지하며, 68 티어도 target 숫자 기준선에 맞춘다. 느낌표 자체를 옮기거나 ULD를 바꾸지 않는다.

- 검사기의 고정96px 캔버스가 큰 글리프 하단을 잘라 측정하던 오류와 공백을 항상8px로 계산하던 오류도 수정했다. 이전 출력은 제목·랭크업 기준선 검사에 실패하고 수정 출력은 통과한다. 100/150/200/300/400%의 기존 티어 모델과 고정 원점 글리프 렌더를 검증했다. 현재0.88 수정본은 사용자가 제공한 게임 화면에서도 마수도감 제목과 랭크업의 크기·상단 잘림·정렬이 정상임을 확인했다. 이 확인을 다른 창이나 모든 배율의 정상 표시로 확대하지 않는다.

### 소지품 제목·일본어 부제 겹침 — 창별 간격 조정, 게임 재확인 대기

- 원본 규격 검증 후 적용하며 일반 폰트 포함/기타 UI 한국어 경로에서만 생성한다. 실제 ULD 생성·재읽기에서 각 파일의 부제 X 하위1바이트만 달라지고, 이전 출력 거부·수정 출력 통과·비대상 변경 검출을 확인했다. native `SetTitle`의 최종 배치 계산은 공개 구현으로 확인되지 않아, 이 조정의 게임 내 겹침 해소는 사용자 재확인이 필요하다.

- 해당 원문 템플릿에 한해 clean 기본 언어의 직업명을 선택하는 동적 문구를 생성한다. 한글 주제와 `ClassJob` 데이터는 변경하지 않는다. 실제 영어 원본의 빈 부제, Base 구성, 비어 있지 않은 한국어 부제, 명시적 보존/치환 정책 및 다른 템플릿은 유지한다.
- 실제 원본 기반 JA/EN 생성·재읽기와 직업46개, 없는 키·범위 밖 선택을 검증했다. 이전 JA 출력은 중복 검사에 실패하고 수정 출력은 통과하며, 이전 출력과 달라진 텍스트 행은 JA `Lobby#1975`뿐이다. 로비 글꼴·ULD 변경은 없다.

### 마수 랭크 발바닥이 등호로 표시됨 — 복원 코드 수정

- `Addon#17889`의 발바닥은 `U+E036`이다. 조사한 배포 TTMP의 비로비 FDT 27개에는 모두 이 글리프가 없었다. 출력 FDT와의 교집합만 보는 방식으로는 이 누락을 필수 복원 대상으로 잡지 못했다.
- 이제 대응하는 clean 글로벌 FDT에 E036이 있는 비로비 경로에만 같은 코드포인트의 글리프와 atlas/mip를 복원한다. KrnAXIS의 기존 AXIS 대응을 재사용하며, 다른 PUA의 폰트 범위는 넓히지 않았다.
- 기존 글리프 할당을 모두 마친 뒤 발바닥을 별도 할당하고 원본 mip 정렬을 유지한다. 빈 원본, 할당 실패, 필요한 텍스처 미출력은 생성 실패로 처리한다.
- 기본 `beastmaster-paw` 검사는 원본으로 증명되는 경로의 누락·빈 형태·등호 폴백·base/mip 불일치를 검사한다. 비교용 `=`나 검증 가능한 발바닥 경로가 없다는 이유로 잘못 통과시키지 않는다.
- 합성 AXIS_12/KrnAXIS_120/MiedingerMid_18 복원, 비정렬 원본 좌표, 기존 기호·숫자·영문·한글·다른 PUA의 네 mip 단계 보존을 확인했다. 실제 백업 전체와 게임 UI 배율별 검증은 아직 수행하지 않았다.

### UI 배율별 큰 한글 라벨

### 마법자판 난타전 단어 입력

- `KTGTypeWordTextData`의 한국어 단어 표시와 한글 입력 판정은 이 저장소에서 실제 게임으로 확인하지 않았다.
- JA 클라이언트는 단어 위에 히라가나 읽기를 표시한다(PR #4 작성자 보고). 읽기 열은 한국 원자료·대상 원문 그대로 유지한다. 한국 원자료도 번역한 단어에 히라가나 읽기를 남겨 둔다.
- 물결표 입력: 게임은 입력한 물결과 단어의 물결이 같은 글자일 때만 맞다고 판정한다. 반각 `~`와 전각 `～`는 같게 보지 않는다.
  - PR #4 작성자: JA 클라이언트에서 띄어쓰기·기호까지 전각으로 입력된 상태(`뭐　하는　짓이야～！`)에서 반각 `~` 단어를 입력하지 못했다. 이에 따라 `v2026.10.29.2120`은 JA 대상 한국어 단어 17개의 `~`를 전각 `～`로 바꿨다.
  - 배포 후 사용자 제보: 입력한 `~`가 반각(위쪽에 그려지는 물결)으로 들어가 전각 `～` 단어가 인정되지 않았다.
  - 한국어 자판은 기본적으로 반각 `~`를 입력하고 한국 클라이언트 단어도 반각이므로, JA·EN 모두 반각 `~`로 되돌렸다(v7.56 기준 각 17개 단어). 한글 입력기가 전각(전자) 모드이면 이 단어들은 인정되지 않는다. Windows 11 Microsoft 한국어 입력기는 `Alt+=`로 전각/반각을 바꾼다는 사용자 보고가 있다. PR #4 작성자의 전각 입력이 입력기 설정 때문인지 JA 클라이언트 동작인지는 확인하지 않았다.

### 텍스트 원문 유지 빌드의 로비 일본어 한자

- 텍스트를 모두 원문으로 두고 폰트를 포함한 빌드에서 로비 Hangul 할당이 로그인 대기 문구(`Error#13206`) 등 일본어 로비 문구의 한자 셀을 덮어쓰던 문제를 수정했다. 원인과 수정 범위는 [HD_FHD_LOBBY_PAGE_BUDGET.md](HD_FHD_LOBBY_PAGE_BUDGET.md)에 기록한다.
- UI에서 9개 결과가 모두 원문인 `선택 구성 패치`는 이제 폰트만 패치(`--font-only`)로 생성하므로 로비 폰트를 바꾸지 않는다. CLI의 전부 원문 `--include-font` 빌드는 clean 텍스트 조사로 보이는 한자를 보호한다.
- clean 텍스트 조사 결과에 해당 문구의 한자가 모두 포함됨을 확인했다. clean `000000` 원본 백업이 없어 전체 폰트 재생성과 실제 로비 화면 확인은 아직 수행하지 않았다.

## 기능 제한

- `ExcelVariant.Subrows` 시트는 지원하지 않으며 진단 파일에 `unsupported-subrows`로 기록한다.
- 퀘스트 Say 문구 익명화는 커버리지가 불완전해 비활성화되어 있다. CLI 옵션은 경고만 출력하는 no-op이다. 말하기 퀘스트에서 한글 입력을 피하는 용도는 `--say-quest-phrases base`(UI `말하기 퀘스트 입력 문구`)가 대신한다.
- 말하기 퀘스트를 베이스 언어로 진행하도록 설정하면 한국어 입력으로는 진행되지 않는다. 게임이 퀘스트마다 정답 문구 하나만 비교하기 때문이다.
- 퀘스트 밖에서 `말하기`로 입력하는 문구는 내장 표 `SayPhrases.tsv`에 있는 것만 원문으로 바꾼다. 공개 데이터(2026-10-13 내보내기)에서 주문을 따옴표로 인용한 안내문과 글자가 같은 행을 찾아 알로알로 섬 주문 3개와 상인 이야기 주문 1개를 넣었다. 안내 없이 공략으로만 알려진 주문은 이 방법으로 찾지 못한다. 실제 게임에서 이 행과 비교하는지는 게임 스크립트로 확인하지 않았으며, 한국어 패치에서 한국어 주문만 통한다는 사용자 제보와 행 내용으로 판단했다.
- 글로벌·한국 클라이언트 버전이 다르거나 clean/original index를 확보할 수 없으면 실제 패치 생성을 중단한다.
- 실제 설치 폴더는 clean 기준선으로 사용하지 않는다. 별도 백업의 restore baseline 또는 산출물의 `orig.*` index를 사용한다.

## 폰트 회귀 방지 규칙

- `font-only` 범위는 [FONT_ONLY_PATCH_SCOPE.md](FONT_ONLY_PATCH_SCOPE.md)를 따른다.
- shared atlas를 수정할 때 `Jupiter_45/90` damage-number route와 `font3.tex`의 기존 한글 영역을 오염시키지 않는다.
- 로비 폰트 변경 전에는 [LOBBY_FONT_REWORK_PLAN.md](LOBBY_FONT_REWORK_PLAN.md), [LOBBY_ROUTE_SURVEY.md](LOBBY_ROUTE_SURVEY.md), [HD_FHD_LOBBY_PAGE_BUDGET.md](HD_FHD_LOBBY_PAGE_BUDGET.md)를 확인한다.
